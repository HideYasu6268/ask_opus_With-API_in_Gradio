# ask_opus_With_API_in_Gradio

## ローカル起動
```bash
pip install -r requirements.txt
export ANTHROPIC_API_KEY=... GEMINI_API_KEY=...        # Geminiは有料枠のキー
export GOOGLE_SERVICE_ACCOUNT_JSON="$(cat sa-key.json)" # ローカル用。DriveのファイルをこのSAのメールに共有しておく
python app.py   # http://localhost:8080
```

## Cloud Run + IAP（仕様書12・13・14章）
```bash
gcloud run deploy consult-agent --source . --region asia-northeast1 \
  --max-instances 1 --min-instances 0 --no-allow-unauthenticated --iap \
  --set-secrets ANTHROPIC_API_KEY=anthropic-key:latest,GEMINI_API_KEY=gemini-key:latest
# 自分のGoogleアカウントにIAPアクセス権（roles/iap.httpsResourceAccessor）を付与
```
Drive認証: 実行SAのADCで `drive.readonly` が使えなければ、SAキーをSecret Managerに置き
`GOOGLE_SERVICE_ACCOUNT_JSON` として渡す。

## 環境変数
`CACHE_TTL`(1h/5m) / `GEMINI_MODEL` / `USD_JPY` / `COMPRESS_CHARS` / `KEEP_TURNS` / `APP_USER`・`APP_PASSWORD`（任意の二重認証）
単価・モデルIDは `config.py`。

## キャッシュの扱い方（重要）
資料（handoff package / 全文）はsystem側に置き、Claudeのプロンプトキャッシュに載せる。
2回目以降の入力料金は、キャッシュ読み取り（約1/10〜1/20）になる。

### 決めておくこと
- **モデル（Sonnet / Opus）は最初に決める。** 切り替えるとキャッシュは引き継がれず、資料も書き込み直しになる。
  Opusで相談すると決めているなら、「資料を追加」を押す**前に**Opusを選ぶ（準備ステップがそのモデルのキャッシュに書き込むため）。
- **思考の深さ（低/中/高）は変えられるが、履歴が長いほど損が大きい。** 変えると会話履歴部分のキャッシュは切れ、
  その分は書き込み料金で払い直しになる（履歴が短い序盤なら数円程度。長くなると増える）。
  資料部分（system側）は残る見込み。画面の警告に、切れる履歴の大きさと追加コストの目安が出る。
  重要な相談は、序盤のうちに深さを決めておくほうが得。
  ただし「資料部分が残る」は未実測。切り替えたあと、画面の実費表示（キャッシュ書込/読取トークン）で確認すること。

### いつまで効くか
- 既定は**1時間**（`CACHE_TTL=1h`）。5分にしたい場合は `CACHE_TTL=5m`。
- 固定の1時間ではなく、**最後に使ってから1時間**。使われるたびに延長される（追加料金なし）。
- 1時間以上あくと切れ、次の送信で書き込み直しになる（概算の「キャッシュなし」側の料金）。
- アプリ側の制約: Cloud Runの再起動・スケールゼロでセッションが消えると、保持している資料も失われる。
  その場合は「資料を追加」からやり直しになる。Geminiが作り直した資料は前回と文面が変わるため、
  Claude側のキャッシュが残っていても使えない。

### キャッシュが切れる主なケース
| 操作 | 切れる範囲 |
| --- | --- |
| モデルを切り替える | 全部（資料も書き込み直し） |
| 思考の深さを変える | 会話履歴部分（資料部分は残る見込み） |
| 履歴を要約した（閾値超過で1回だけ自動） | 会話履歴部分 |
| 資料を追加した | 会話履歴部分だけ（前の資料は残る） |
| 最後の使用から1時間（TTL）経過 | 全部 |

### 確認方法
送信後に表示される実費の内訳（通常入力 / キャッシュ書込 / キャッシュ読取）を見る。
キャッシュ書込が毎回大きい場合はキャッシュが効いていない。資料準備時に「キャッシュに書き込まれていません」と出たら、
資料が最小キャッシュ長に満たない可能性がある。

### 画面での表示（app.py）
資料を追加したあとは、画面に資料キャッシュの状態が常時表示される。
- 有効 / 期限切れ（残り時間つき。使うたびに延長される）
- モデルを変えたとき、思考の深さを変えたときの警告（送信前に表示される）
- 別モデルで送信した場合は、その送信でキャッシュが書き込まれるため、以降はそのモデルが基準になる
- 表示の残り時間は、画面操作・送信のたびに更新される（自動更新はしない。Cloud Runをスケールゼロにするため）

## 資料は追加方式（展開に応じて足していく）
「資料を追加」を押すたびに、新しい資料が**後ろに足される**。古い資料は消えず、並びも中身も変わらない。
```
[指示] → [資料1] → [資料2（追加）] → [会話履歴] → [今回の相談]
```
- 資料1はキャッシュから安く読まれる。追加した資料2と、会話履歴の書き込みだけが今回のコストになる。
- 追加の直後に、今回の追加コスト（実費）と、キャッシュ書込・読取のトークン数が画面に出る。
- 追加のとき、相談欄に入っている文章がGeminiへの手がかりになる。次に知りたいことを書いてから追加すると、関連箇所を拾いやすい。
- 追加に失敗しても、今までの資料は残る。
- リセットボタンはない（誤操作防止）。話題が変わったら、ページを再読み込み（iPhoneのホーム画面アプリはアプリを終了して開き直す）。履歴も資料もすべて消える。
- キャッシュ境界は新しい側の2つの資料に置く（上限4個のうち、履歴用に1個を残すため）。資料を何回足しても、境界は増えない。
- 資料を追加するときにモデルを変えると、全部の資料が新モデルで書き込み直しになる（追加コストの表示が大きくなる）。
